# Mac 0.5.10 Verification

Release authorized by the owner on 2026-11-16, invoked through `general-release`
(`/general-release`). Mac version 0.5.10, build 20, Apple Silicon, minimum deployment
target macOS 14.0. Runtime checks ran on macOS 26.5.2 (25F84); no separate macOS 14
runtime test was performed. Kinrox Remote is unchanged (0.2.2, build 4).

## Contents

- Settings → Default Video Player (Figma `312:387`, component `312:454`): one click makes
  Kinrox the system-wide default for MOV, MP4, M4V, MKV, WebM, AVI and TS through
  `NSWorkspace.setDefaultApplication(at:toOpen:)`; status per format, cancelled system
  confirmations are not errors. Motivation: macOS refuses quarantined files opened through a
  per-file "Open With" binding to a non-default app ("Apple could not verify … is free of
  malware"), reproduced on 2026-11-16; opening through the system default does not.
- `Scripts/unregister-dev-copies.sh`, run at the end of `build-release.sh`, removes
  build and staging copies of `app.kinrox.player` from LaunchServices so Finder's "Open With"
  lists only the installed app.
- Review fixes (agy review, Codex apply, orchestrator control): the failed state clears when
  every format already opens in Kinrox; MKV/WebM fall back to the imported types if the
  extension lookup is dynamic; single-line button; cleanup-script path handling with an
  isolated fake-`lsregister` test.
- App Review drafts for Kinrox Remote (`AppStore/review/DEMO-VIDEO.md`, `notes.txt`) ship as
  is by owner decision; `notes.txt` still holds the `<DEMO_VIDEO_URL>` placeholder, to be
  filled before any fastlane metadata upload.

## Verification boundaries

Performance was not measured: the package does not touch Spotify playback, Music memory or
startup, and the new card is created only when Settings opens. The Default Video Player
button was not pressed against the real system defaults; the behaviour of
`setDefaultApplication` (silent success when assigning Kinrox, `userCanceledErr` for a
console process reassigning another app) was observed in a manual probe on 2026-11-16, and
the app's handling is covered by unit tests. Interactive mounted-app playback and
physical-phone pairing against the release DMG were not performed. Physical sleep/reboot
checks remain waived, not passed.
